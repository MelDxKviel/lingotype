# Добавление учебных текстов

Для добавления текстов всегда используй **пакетную генерацию строк с разделителем `|` через Node.js-скрипт**. Учебный материал пишет и редактирует агент; повторяющиеся ключи, ID и JSON-разметку создаёт скрипт. Это экономит токены на служебной структуре, особенно при больших партиях.

1. Прочитай [правила контента](content/README.md) и [пример скрипта](scripts/examples/add-content.mjs). При добавлении текстов эта инструкция заменяет ручное копирование JSON-объекта из README; все языковые и структурные правила README сохраняются. Исходный код приложения читать или менять не требуется.
2. Зафиксируй число **новых** текстов по уровням и распределение по темам. Посмотри существующие тексты нужных тем, чтобы избежать смысловых повторов. ID и количества вычисляй программно; выводи только нужные строки и краткие сводки, без всей JSON-коллекции.
3. Скопируй пример в `output/add-content.mjs` (`output/` исключён из Git). В копии замени `expected` на заказанные количества и демонстрационные вызовы `add` на свои пакеты. Сохраняй готовую логику обработки; при обычном добавлении меняются только план и строки материала.
4. Генерируй по одному тексту на строку, без ключей JSON и кавычек вокруг отдельных полей. Для каждой темы используй один `add(topic, source)`; уровни внутри пакета могут различаться.

```text
level|title|text|translation|phrase|meaning|note|example
```

В самом пакете строки заголовка нет. Пример:

```js
add('travel', `
A2|Свободные руки|We left our bags at the station. Now we can explore the town without carrying them.|Мы оставили сумки на вокзале. Теперь можно гулять по городу, не таская их с собой.|left our bags|оставили наши сумки|Leave something somewhere — оставить вещь в определённом месте. Left — прошедшая форма leave.|We left our bags at the hotel.
`);
```

По умолчанию в строке 8 полей и одно выражение. Для второго или третьего выражения допиши ещё одну или две группы `|phrase|meaning|note|example`: получится 12 или 16 полей. Скрипт поддерживает все три варианта.

Символ `|` зарезервирован для разделения полей, а перенос строки — для следующего текста. Внутри полей они запрещены; каждое поле должно быть непустым, без пробелов по краям. Обычные `'` и `"` не требуют экранирования внутри шаблонной строки JavaScript. Обратный слеш, обратную кавычку и последовательность `${` нужно экранировать по правилам JavaScript. Пустые строки между материалами не вставляй.

5. Выполни `node output/add-content.mjs`: по умолчанию скрипт только проверяет данные и показывает количества. Исправь найденные ошибки. Проверь естественность английского, точность переводов, уровни и объяснения выражений.
6. Выполни `node output/add-content.mjs --write`, затем `npm run validate` и `git diff --check`. Сверь diff и число добавлений с поручением. Если нужно обновить `dist/`, выполни `npm run build`.
7. Удали временный скрипт после завершения. В репозитории остаются готовые JSON-файлы; общий пример изменяй только при необходимости изменить сам метод.

Пример скрипта проверяет весь пакет до записи, создаёт уникальные ID, продолжает нумерацию темы, сохраняет существующие объекты и форматирование. Повторный запуск с теми же текстами завершается ошибкой до записи. Исправляй уже добавленные материалы по их ID, сохраняя прежние пользовательские изменения.

Пример рассчитан на существующие темы из `catalog.json`. Для новой темы адаптируй копию скрипта: выбери уникальный префикс, начни нумерацию с `01`, создай JSON-массив и добавь тему в каталог согласно README.
